Rocks'n'Diamonds for MS-DOS
===========================

Rocks'n'Diamonds 4.4.2.4 built for MS-DOS / FreeDOS as a 32-bit protected-mode
(DPMI) program: the full game at its normal 672x560 screen, sound and music,
long file names, and network games over TCP/IP.

It is the normal Rocks'n'Diamonds source (an SDL2 program) on SDL3's DOS
port, through sdl2-compat, with SDL2_image, SDL2_mixer and SDL2_net
(on Watt-32) underneath, as in SDLPoPDOS.


Running it
----------

Copy the RND folder (`make dist`) anywhere and run RND.EXE from it.

    C:\RND> RND
    C:\RND> RND --network              network game (see below)

Requirements:

  * A long file name driver: DOSLFN (vmdos loads it), or Windows 9x.
    The game's data uses long names (levels\Classic_Games\...).
  * Pentium or better, 128 MB of RAM. The game's own tables take about
    80 MB before anything is loaded (on DOS all of it is in use from the
    start); with less, CWSDPMI stops with a General Protection Fault.
  * VESA BIOS with a mode of at least 672x560 (800x600) in 15, 16, 24 or
    32 bits per pixel.
  * Optional: Sound Blaster (Pro or 16) or compatible, BLASTER set.
  * Optional: mouse driver, gameport joystick.
  * For network games: a packet driver (vmdos: VMPKT).

DOSBox: use DOSBox-X, with the dosbox-x.conf in the RND folder (long file
names on, 128 MB). Plain DOSBox has neither long file names nor more than
63 MB, and RND.EXE stops at once there.

    cd RND
    dosbox-x -conf dosbox-x.conf

Settings, scores, tapes and your own levels go in RND\userdata (or in
%HOME%\userdata when HOME is set). The log is userdata\rnd.log;
`RND --debug > COM1` sends it to a serial port as well.


Video
-----

The game screen is drawn 1:1, centered, in the smallest VESA mode that holds
it (800x600), at the most bits per pixel the card has. SET RND_VIDEO picks
another mode:

    SET RND_VIDEO=800x600x16       fewer bytes to copy on slow cards
    SET RND_VIDEO=1024x768x32


Network games
-------------

Load the packet driver first. WATTCP.CFG (next to RND.EXE) has Watt-32 get its
address by DHCP; put `my_ip`, `netmask`, `gateway` and `nameserver` there for
a fixed one.

    C:\> VMPKT
    C:\RND> RND --network                  find a server on the LAN, or be one
    C:\RND> RND --network 192.168.1.10     join that server (port 19504)

DOS, Linux, Windows and Mac players can play together (same game version).
A DOS PC can also be the server for the others.


Building
--------

GNU make and Perl (the game generates some of its source), and either Docker
or a DJGPP cross compiler on the PATH (i586-pc-msdosdjgpp-gcc; prebuilt:
https://github.com/andrewwutw/build-djgpp/releases). As in SDLPoPDOS, the
local compiler is used when there is one, otherwise the djfdyuruiry/djgpp
Docker image, which the Makefile pulls.

    cd msdos
    make            # libraries, the game: rnd.exe (CWSDPMI inside) + data here
    make DOCKER=1   # compile in the Docker image even with a local compiler
    make DOCKER=0   # never use Docker
    make dist       # build/dist/RND: the folder for a DOS disk
    make DEBUG=1    # build-debug/: frame pointers and symbols, for crash tracebacks
    make clean

What is here:

  * SDL3/, sdl3-config/, cwsdpmi/ -- as in SDLPoPDOS.
  * deps/ -- sdl2-compat, SDL_image 2.8, SDL_mixer 2.8, SDL_net 2.2, libxmp
    (lite), zlib, Watt-32. Changes for DOS are marked "DJGPP"/"msdos":
      - sdl2-compat: SDL3 is linked in, not loaded; the Makefile renames
        SDL3's SDL_* symbols to S3_SDL_* and src/sdl3_dos_table.c maps them.
      - SDL_net: Watt-32 sockets; SDLNet_CheckSockets() waits in steps so
        SDL's cooperative DOS threads (the network server, sound) keep running.
      - SDL_mixer: fixes a heap overflow in Mix_LoadWAV_RW() on the
        release-2.8.x branch (commit 6581297b sizes the conversion buffer
        before setting its length).
      - Watt-32: watt32-djgpp.err and watt32-syserr.c, generated by running
        Watt-32's dj_err.exe under DOS (it can't be run when cross-compiling).
  * src/ -- dos_main.c (starts the game through SDL3's SDL_RunApp) and
    sdl3_dos_table.c.

Changes in the game's own source (../src), all under `#ifdef __DJGPP__`:

  * libgame/sdl.c: the VESA mode choice above; no window resizing.
  * libgame/misc.c: fileExists()/directoryExists() answer from a cache of the
    data directories (graphics, sounds, music, levels, conf, docs): the game
    checks ~14,000 file names at startup, and each costs DOS a directory
    search; readDirectory() takes the entry type from readdir() instead of a
    stat() each; the log is committed at each line.
  * libgame/setup.c, main.c: user data in RND\userdata.
  * libgame/zip/ioapi.h, game_bd/bd_random.c: DJGPP has fopen() for
    fopen64() and no clock_gettime().
